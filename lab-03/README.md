# Лабораторна робота 3 — власний DevOps-інструментарій

Автор комітів: **w1xes**. Робота ведеться в окремій гілці й здається через PR у `main`.
Команди нижче виконуються з кореня репозиторію, якщо не вказано інше.

## Резервне копіювання

Потрібні Bash 4+, GNU tar/coreutils, util-linux (`flock`).

```bash
./lab-03/backup.sh --help
./lab-03/backup.sh --source 'my project' --dest '/tmp/my backups' --keep 3
./lab-03/backup.sh --source 'my project' --dest '/tmp/my backups' --keep 3 --dry-run
```

Обов'язкові `--source`, `--dest`; `--keep` типово 5, лише додатне ціле число.
Джерело має бути доступною для читання текою; призначення створюється автоматично.
Призначення всередині джерела та джерело `/` відхиляються, щоб архів не включав сам себе.
Ім'я архіву: `my project-<hash канонічного шляху>-2026-10-20-190000-123456789.tar.gz`.
UTC та наносекунди забезпечують сортування й окремі імена для швидких запусків.
Hash розрізняє різні джерела з однаковим basename. Ротація чіпає лише звичайні
файли відповідного джерела з точним форматом імені. Інші файли й symlink збережені.
Архів спочатку пишеться у тимчасовий файл, потім перейменовується; `flock`
серіалізує одночасні запуски для одного джерела. При помилці tar ротації немає.

Приклад виводу (мітки та розміри залежать від запуску):

```text
Created /tmp/my backups/my project-<hash>-2026-10-20-190000-123456789.tar.gz
2026-10-20T19:00:00Z action=backup result=success archived_files=1 archives_created=1 deleted=1 archive_bytes=170
```

Журнал: stderr і `BACKUP_LOG` (типово `./backup.log`, батьківська тека має існувати).
У dry-run **немає жодних файлових змін**, навіть журналу/lock-файла; журнал і
повний план створення/видалення друкуються в термінал. Dry-run рахує ротацію
з урахуванням майбутнього нового архіву.

Коди: 0 успіх, 2 параметри, 3 джерело, 4 призначення/блокування,
5 архівування, 6 ротація, 7 запис журналу.

### Навіщо `set -euo pipefail`

- `-e`: зупиняє скрипт при неврахованій помилці команди. Без нього після
  невдалого архівування можна було б перейти до видалення старих копій.
- `-u`: звернення до невстановленої змінної — помилка. Без нього друкарська
  помилка в назві шляху перетвориться на порожній рядок і змінить дію команди.
- `pipefail`: конвеєр невдалий, якщо невдала хоча б одна його команда.
  Без нього успішний `wc` приховав би помилку `find` під час підрахунку файлів.

Критичні операції додатково перевіряються явно: `-e` має винятки, зокрема в `if`.
